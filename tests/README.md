# Tests

Headless-Chrome checks used in the Nov 2026 quality check. Run them from the repo root after rebuilding `index.html`; each prints a short report. Screenshots and pictures go to `tests/out/` (not committed).

Needs Python 3 with `playwright` (and `pillow` for the icon preview). Chrome is taken from `$CHROME`, `/usr/bin/google-chrome`, or Playwright's own Chromium.

| Script | What it checks |
|---|---|
| `harness.py` | Shared helpers: local server, phone sizes (`iphone12`, `small` 320×568, `big` 430×932, `sideways` 844×390, `desk` 1280×800), opening a game, console errors. `iphone12` simulates the user's home-screen app (see its docstring). |
| `layout_compare.py [ref]` | Template positions of every game (and both flipped 2-player modes) at all five sizes, compared with `index.html` at a commit (default `HEAD`). Use it after any change to catch layout shifts. |
| `resume_check.py` | Saved games come back after a reload (Knucklebones also mid-CPU turn, Othello, Water Sort, Sudoku); a finished game adds to the record and starts fresh. |
| `remi_check.py [rounds]` | Remi auto-play at Easy/Norm/Hard with a rule check (all 106 tiles accounted for, every formation valid, every CPU take from the discard row follows your rules: opened first, never the first tile, with 3 tiles only the last discard, the taken tile laid in a new formation that turn, every CPU opening has 45+ with a run and a set or is a set of 1s), then reload after a draw keeps the drawn tile, an empty pile is refilled from the discards, and the round counter above the rack equals your real round score when a CPU closes and stays, adding up to your Round score, on the round results (and the line after a draw doesn't name the tile). |
| `install_check.py` | Manifest and Android installability errors (none expected) served from a subfolder like the live site and from the root, then offline opening at `/`, `/index.html`, `?fbclid=x`. |
| `icon_preview.py` | `icon-maskable.png` cut to the common Android launcher shapes (writes `tests/out/android_icon_preview.png`). |
| `colour_blind_check.py` | How far apart the colours that carry meaning stay under the three kinds of colour blindness (Water Sort liquids, Remi tile colours, Othello discs). Needs `numpy` and `scikit-image`. |
| `a11y_check.py` | Text contrast and tap-target sizes on the cover and every game (game, Rules, Settings), plus colour-blind screenshots of Water Sort and Remi in `tests/out/`. Dimmed (switched-off) buttons are listed too; those are expected. |
| `save_fuzz.py game port` | Damaged saved data: each saved value garbled, cut, or with fields deleted / of the wrong type, and storage blocked. The game must still open and play, with no "undefined"/"NaN" on screen or in Settings. Closes any open game before damaging the values (Sudoku saves itself when the page closes). |
| `referee.py oth\|kb [games]` | Auto-played Othello and Knucklebones games checked move by move against an independent copy of the rules. |
| `puzzle_check.py sdk N` / `puzzle_check.py ws` | Sudoku puzzles have exactly one solution (independent solver) and play through; Water Sort levels are solved by a separate solver and played by tapping with Accessibility on. |
| `core_check.py` | What every game gets from the shared core, in each of the five: Rules open the first time only, panel toggles / outside tap / Escape, Sound and Scanlines shared and reset on reopening, a hidden game is quiet, "Tap again" on the red button, Exit, Remi forgets Medias on Exit and Back. |
| `mouse_scroll_check.py` | Remi with a mouse at laptop size: the wheel slides the discard row and a wide Landscape rack, table / discards / rack can be dragged, a drag never taps a tile, a plain click still does. |
| `build_check.py` | `index.html` is exactly what `games/build.py` makes from the sources (packed fonts left out of the comparison). |
| `style_snapshot.py save NAME [folder] [sizes]` / `compare A B` | For clean-ups that must not change the look: records every element's position and styles on every screen (cover, games in play, Rules, Settings, flipped modes, stress states, Remi Medias and Landscape) at six sizes, with fixed random numbers; `compare` lists every difference. Two snapshots of one build compare equal. |
| `device_sweep.py [sizes]` | Every screen (cover, games, Rules, Settings, flipped modes, Remi Medias and Landscape, stress states) at 36 screen sizes: phones, tablets, laptops. Nothing cut off, outside the stage, overlapping or clipped; no errors. About 25 min for all sizes. |
| `monkey.py game port seed [x] [rounds]` | Random fast taps, double taps and reloads, then consistency and stuck-CPU checks. Run one or two at a time (many at once time out). |
| `exit_check.py` | Exit always brings back the cover: normal window, a window that ignores the step back (Chrome app installed on Windows), several instant taps on Exit or a card, and the Back button. |
| `ai_tournament.py [kb\|oth\|remi\|all] [N] [--seed S] [--slow] [--vs] [--base] [--styles] [--person] [--imagine]` | CPU levels bot against bot with fixed seeds: Knucklebones and Othello every pairing of Easy / Normal / Hard / Random (targets 75% and 95%), Remi two levels per table, both seatings on the same deals (points per round with the gap ± its standard error, closes, takes from the discard row; a never-shipped build where all four seats are CPUs; `--vs` plays today's CPU against the one from before the AI build, `tests/fixtures/remi_cpu_base.js`, level by level, `--base` the old levels against each other; `--styles` the three Remi personalities per level: each against the plain level, then the game's table and the styles moved round the CPU seats, played as matches to 1000 (and the game's table to 500) because the CPUs play the score, with the share of matches each style wins, target a third each give or take 5 points, and how each one plays; `remi 4000 --styles` takes about 35 min; `--person` playing like a person, per level: the CPU against itself without the new habits, each habit on its own, score play in matches, how often each habit shows (tiles thrown that fit the table, adds and takes overlooked, discards forgotten, fishing, small openings) and how long the pauses are; `remi 2000 --person` takes about 12 min; `--imagine` Hard's timing and imagined hands (step 5): all of it against the Hard of step 4b, the imagined hands at each speed's number of tables, then each part on its own (discards, take or draw, closing with a 1 or joly, the board game by expected points, weighing the atu) and how often the imagined tables decide; `remi 1200 --imagine` takes about 50 min). `--slow` times decisions at 4× CPU slow-down (Othello also plays one real game per level through the page, CPU in its Worker, counting main-thread tasks over 50 ms; Remi times every CPU decision of 12 rounds per level, Hard at each speed's number of imagined tables against the shortest pause such a choice can have, and plays Hard at the real pace at all three speeds with its Worker: how long each imagined answer takes against the pause of that move, answers that came late, main-thread tasks over 50 ms). Remi tournaments work out Hard's imagined hands in the page (`__ai.main`), with the number of tables of Fast speed unless the mode says otherwise, so the same seed gives the same numbers; Hard makes them slow (a table of four Hard CPUs plays about 3 rounds a second). Numbers in `tests/out/ai_tournament.json`. Same seed, same numbers. About 15 min for all. |
| `ai_kit_check.py` | The CPU brain kit in `core.js` in every game: seeded randomness, mistake model, look-ahead timer, thinking pause and cancelling, Worker and its fallback, level knobs and player adjustment (damaged saves ignored), never touches `Math.random`. |
| `remi_fair.py [rounds]` | Remi fairness: the CPUs decide from public information plus their own hand. Plays whole rounds with four CPUs and checks every decision: no hidden tile in the CPU's view (pile and other hands only as counts); shuffling the hidden tiles changes neither the view nor the answer; the decision functions, copied into an empty page with no game and `Math.random` switched off, give the same answers from the views and seeds alone; their source never names the game state. The rounds are played as matches and the scores in the view must be the ones on the score table (and, since step 5, the atu's holder, the points each player has on the table and the speed setting the ones everyone sees). Hard's Worker: a sample of its discards and takes, asked again in the Worker the game uses, must get the same answers. Also proves the leak check can fail. About 30 s; exit code 1 on any problem. |

Notes: Water Sort keeps its state inside the page's closure, so deep scripted tests of it need a test-only copy of the game that exposes it (never committed). Real-phone things (iPhone clipping, Android launchers) still need a real device.

## On GitHub
`.github/workflows/checks.yml` runs `build_check`, `layout_compare origin/main`, `exit_check`, `core_check`, `resume_check` and `install_check` on every pull request. These six end with exit code 1 when something is wrong (`harness.strict()` turns a printed `False` or console errors into a failure); the other scripts only print what they find.
