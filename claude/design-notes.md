## Workflow
- Work and test locally; push only when the user says "deploy" (= push a branch, open the PR, **wait for the `checks` run on it to pass**, merge it; no review needed). `main` is the live site (GitHub Pages).
- Automatic checks (PR #71): `.github/workflows/checks.yml` runs on every pull request: `build_check` (index.html is a fresh build of the sources), `layout_compare origin/main`, `exit_check`, `core_check`, `resume_check`, `install_check`; about 5 min. Poll `gh api repos/Need4INK/neon_arcade_90s/commits/SHA/check-runs` until `checks` is `completed` / `success`. If a check fails, fix it first; don't merge around it. Pushing the workflow file through the Claude connection worked.
- In Claude Code sessions `gh pr create` (GraphQL) is blocked: use the REST API (`gh api repos/Need4INK/neon_arcade_90s/pulls …`, then `-X PUT …/pulls/N/merge`) as **two separate calls**. Pushing needs the repo added to the session with push access. The auto-mode check may block the merge or running `games/build.py` from a fresh clone; it goes through once the user confirms in the chat ("merge"). It may also block adding the repo with push access at the start (Nov 11–13); the read-only clone (`add_repo` with read access, at `/home/claude/need4ink/…`) works for local work, and adding push access went through once the user said "deploy" (the push clone lives at `/home/claude/neon_arcade_90s`; carry the work over as a patch). On Nov 15 adding push access at the start worked directly, and the whole deploy (push, REST PR, checks poll, squash merge) went through without extra confirmation. The Pages build status can't be read through the proxy.
- A deploy turn can be cut off (the cloud session restarts): on "deploy", first look at `git log`, `git ls-remote --heads origin` and the open pull requests. If the branch and PR already exist, compare them with the local work (PR #72: commit and PR were already there, checks green; only the merge was left) instead of pushing again.
- Commit before `git rebase` (a dirty tree stops the rebase, and a chained push then pushes an empty branch; harmless, it gets the commit on the next push).
- Branches can't be deleted through the Claude Code connection; GitHub deletes each branch on merge ("Automatically delete head branches" is on). Only `main` should exist.
- Preview before deploying: publish the built index.html as a private artifact ("Neon Arcade (preview)"); it doesn't show the real home-screen fit. Republishing it was blocked by the auto-mode check on Nov 13 when the user hadn't asked for a preview; hand back the files instead.
- After a deploy the user fully closes and reopens the home-screen app; Pages takes a minute or two (check screenshot times).
- Layout ideas: try them on the screen test repo first (https://github.com/Need4INK/iPhone12_screen_test, live at https://need4ink.github.io/iPhone12_screen_test/); it can hold a copy of the next build (`arcade.html`). Shared with the arcade's Safari storage (same origin); accepted.
- Look choices: render the options on the real game (inject CSS, screenshot), on every colour involved; the user picks from the pictures. Generic mock-ups mislead (the Remi ripple's cyan blended with cyan blue tiles in the real game). A quick layout sketch (inline SVG) was fine for placing elements (Remi landscape, Nov 12). Labelled side-by-side composites (PIL, 2×2 or 3×2: now vs options, short labels) worked well (iPad landscape, Medias number shadow, Medias Atu).
- Design questions: when the user asks for options or an opinion (e.g. secret Medias, Nov 15), give a short numbered list with a recommendation; build only after they pick.
- Matters of taste "one at a time": one AskUserQuestion per item (also used for the 14 QA pass 9 decisions, numbered "N of 14").
- iPhone simulation in headless Chrome: viewport 390×797, `screen` 390×844, `window.__SAFE` on the cover, inject `.bar{padding-bottom:34px}` into each game (harmless now: the core's `main>.bar` rule outranks it). Real-phone-only problems (clipping of fixed elements): show measurements on the phone and ask for a screenshot. iPad simulation: viewport = screen 1180×820 (iPad Air) or 1024×768, `has_touch`, `__SAFE={t:24,b:20,l:0,r:0}`. Windows laptop browser windows: 1366×657, 1536×730, 1920×945, `__SAFE` all 0, no touch (the user plays Remi Medias on a Windows laptop with a mouse).
- Headless Chrome is not Safari: drawing tricks (blend modes, overlays, SVG filters, SVG clip paths) can look right here and wrong or blurry-when-zoomed on the iPhone/iPad (Remi numbers, PR #65–#67). Prefer plain drawing and ask for a screenshot after deploying.
- The live site can't be fetched from the shell (proxy 403): use a local `http.server` (service worker runs on localhost; add `Cache-Control: max-age=600` to mimic Pages).
- The packed page's CSP blocks `eval`: Playwright `wait_for_function` with a string fails; poll with `evaluate`.
- Test state access: Sudoku, Knucklebones, Othello use page globals; Remi has `window.__remi` (its own functions aren't reachable; hook state, e.g. `G.disc.splice` / `G.disc.push`, which is how `remi_check.py` watches CPU takes and discards; `__remi.viewOf(p)` and `__remi.brain` are the CPU's view and decision functions; tile id = colour×13 + number − 1, +52 for the second set, jolys 104/105); Water Sort keeps state in a closure (read `ws_game` from localStorage or use a never-shipped test copy). The core's `sndOn`, `AC`, `naKeep`, `panel`, `showPanel` are globals in every game frame. For deeper Remi checks, a never-shipped copy in /tmp with `ev:s=>eval(s)` added to `__remi` (rebuilt there, served with `start_server(port, root=…)`) reaches everything; e.g. show round results at once with `__remi.ev("G.phase='play';endRound(1,G.pl[1].hand[0],'')")`, fill the discard row with `__remi.ev("G.disc.push(...G.pl[1].hand.splice(0,6));render()")`. Formations on the table without the test copy: set `__remi.G.melds=[{t:[ids],o:owner},…]` and push to `G.disc`, then tap Sort (that re-renders; the `STRESS` snippets in `tests/device_sweep.py` build a full table, big hand and scores this way, `FULL` in `tests/mouse_scroll_check.py` builds 32 small formations). In the draw phase a tap on a rack tile does nothing: tap Draw first. Measuring rects in the turned (upright phone) Landscape gives rotated values; measure at 844×390 instead, or add up `offsetTop`. A doubles-swap test can set up the deal through `__remi.G` (hands, `cur`, `starter`, `tn=0`, `phase='dbl'`), then `sel.add(id)` and `hSwap()`. Auto-playing a Remi round for screenshots: per phase click Play / Draw, in `play` lay `__remi.openFor(hand)` / `findBest(hand,1,false)` melds via `sel` + `hLay()` (from `G.tn>=4`), then discard the last rack tile; speed via `__remi.spd=2`. Remi always opens in Neon (skin/layout not saved since PR #61): to test Medias / Landscape, open Remi and either click the title 5 times (`main>h1`, within 2 s; PR #73) or click Settings › Skin with JS (`document.querySelectorAll('#sSkin button')[1].click()`; the Skin row is hidden in Neon since PR #73, so a Playwright `f.click` on it would fail, but the existing tests use `evaluate` and still work) and Layout (`#sLay button`[1]); `remi-rules-seen` skips the first Rules. Bar buttons by id in every game: `bRules`, `bSet`; Exit is `#bar .mnu`.
- Damaging a saved game in a test: a game left open can save itself when the page closes (Sudoku does, on `pagehide`) and overwrite the damaged value. Remove the iframes first (`save_fuzz.py` does), or set the game's state to null.
- Ready-made checks in `tests/` (see `tests/README.md`), run from the repo root after rebuilding, output to `tests/out/`: `harness.py` (server, phone sizes, iPhone 12 simulation; card ids `kb`, `oth`, `ws`, `sdk`, `rem`; helpers `open_page`, `open_game`, `game_frame`, `close_panel`, `to_cover`; `strict()` makes a printed False or console errors end with exit code 1), `build_check.py`, `layout_compare.py` (template positions vs any commit; 40 screens; checks banner and bar only, not what's inside the game area), `core_check.py` (shared behaviour in every game: first Rules, panel, outside tap, Escape, Sound/Scanlines sharing, "Tap again", Exit, Remi Back, Remi's secret Medias taps since PR #73), `mouse_scroll_check.py` (Remi with a mouse at 1366×657), `style_snapshot.py` (before/after for clean-ups: every element's position and styles on 41 screens × 6 sizes, random numbers fixed; two runs of one build compare equal; `save NAME [folder] [sizes]`, `compare A B`; about 5 min per snapshot), `device_sweep.py` (36 screen sizes incl. stress states; about 25 min), `resume_check.py`, `remi_check.py` (rules auto-play incl. openings, the CPU take rules, refill, round counter; takes ~5 min, run it in the background), `remi_fair.py` (the CPUs decide from public information plus their own hand; about 30 s since step 5), `install_check.py`, `icon_preview.py`, `colour_blind_check.py`, `a11y_check.py`, `save_fuzz.py` (about 8 min a game), `referee.py`, `puzzle_check.py` (`sdk N` needs a count), `monkey.py` (one or two at a time), `exit_check.py`. ## How the pack works
- `index.html` is built by `games/build.py`: each game embedded as text in its own full-screen iframe (`srcdoc`), so games never clash and a game in progress survives switching. Build: `python3 games/build.py games/Knucklebones.html games/Othello.html games/Water_Sort.html games/Sudoku.html games/Remi.html index.html`
- Shared core (PR #71, user: "one shared core", "remove old layouts"): what all five games share is kept once in `games/` and put into each game by the build. `core.css` (first `<style>` in the head, so a game's own rules can differ from it): palette, page, the template in both forms, title, bar with Exit, Rules/Settings panel, rows, switches, action buttons, touch, hover, reduced motion. `stage.js` (head, runs before the page is drawn): scales/turns the block, sets `html.rot` / `r270` (scanlines follow a sideways picture) and `--st`, `--sh`, `--stw`. `core.js` (right in front of the game's own script): `audio`/`tone`/`sfx`, sound unlock, `showPanel`, `setSw`, panel placing, outside tap / Escape, `naFirstRules`, the Sound and Scanlines switches and their sharing, Exit, "Tap again" (`naArm(button, fn)`, `naDisarm`). A game sets `naSfx` (its sound table) and `naSync` (refresh of its Settings rows), and its file ends with a short "differs from the shared core" block. Knucklebones keeps its own `sfx(n, delay)`. Game files no longer work when opened on their own (accepted). The five game files went from 219 KB to 171 KB plus 13 KB of core; the page stays about 342 KB (344 KB after PR #73) because the core is packed into each frame (possible later: pack it once on the cover and let games copy it, like the fonts, about −50 KB).
- The build still packs fonts and QR and wraps everything in the cover. The Exit button is in each game's markup (`<button class="mnu">`); the core closes any open panel (sends Escape), then calls `parent.kbShowCover()`.
- `kbShowCover()` shows the cover at once, then removes the game's history entry with one `history.back()` (an installed Windows Chrome app never fired the `popstate` the old version waited for). Presses during the step back are ignored (`leaving`, 1.5 s); opening a game while a game entry is current replaces it. `showCover()` first tells the game on screen it is being left: `naPause()` (stops the silent sound loop) and `naLeave()` if the game has one (Remi: forget Medias).
- The URL never changes (no `#game`): bookmarks and the home-screen app always open on the cover. Page title "Neon Arcade"; `apple-mobile-web-app-title` sets the home-screen name.
- The cover page itself (in `build.py`) still has its older layout with `html.stg … !important` rules on top; left alone in PR #71 because it holds the iPhone frame handling.

## iPhone frames
- Each home-screen icon is its own app: frame (solid / see-through status bar) fixed when added; own saved data.
- iPhone 12 measured: `innerHeight` 797, `screen.height` 844, `100svh`/`100dvh` 797, standalone true. Solid icon: insets 0/34. See-through icon (the one the user keeps): insets 47/34, page starts behind the status bar but the fixed layer is cut at 797.
- Fix: the cover detects see-through (top inset > 0, portrait, `innerHeight < screen.height`, `innerHeight + top inset == screen.height`), adds `html.full` and `--fullh`; html/body are that tall with overflow hidden, cover and game iframes `position:absolute`; touchmove blocked. Once full, iOS may report `innerHeight` 844: both 797 (+inset) and 844 count as full (avoids flicker).
- Rotation: iOS updates insets late; the cover re-checks at 100/300/600/1000/1600 ms after rotating and on pageshow / foreground.
- Old solid icons keep a status-bar band; backgrounds fade from `#07030f` over the top 64px so there's no seam. Re-adding the icon gives the see-through frame.

## Three-area template (live since PR #23; in `core.css` since PR #71)
- iPhone 12, top to bottom: safe top 47 · banner 64 · game area 667 · bar 36 (buttons flush with its bottom: padding 22px 0 0) · gap 30 = 844.
- The 390 × 797 block is scaled as one: `naCalc` (shared by the cover and `stage.js`) places a fixed stage below the top inset, k = min(width/390, (height − top inset)/797), centred; bottom inset ignored (the gap covers the home bar). No narrow-phone or short-screen variants any more (PR #71, user): every screen is the same block, only scaled; Settings buttons 64px everywhere.
- Game elements are centred by title `margin-bottom:auto` and bar `margin-top:auto`. Knucklebones: 8pt above/below the boards, boards grow (`flex-grow:8`). Remi (PR #57, user): the game fills the game area 8pt clear of banner and bar (`#game` flex 1, `#table` flex 1 1 0 with `height:auto!important`, min 96; now at the end of Remi's own CSS); the table takes all the room left (about 360 tall on the iPhone 12, was ~270 and never taller than wide), shrinks when the rack needs a third row, scrolls when melds overflow. Water Sort tubes max 64px wide.
- Landscape block (PR #58, only Remi's Medias Landscape, `html.lnd`): `stage.js`'s `st()` (exposed as `window.naSt`, called by the game when the class changes) uses a block 750 wide (`NA_W`, width via `--stw`; 750 = iPhone 12 landscape minus the 47 side insets, so k = 1 there). Height (PR #62, Nov 12, user: iPad had empty bands above and below and the results scrolled): `NA_H = clamp(390, round(750 × ch / cw), 560)`, where cw/ch are the available width/height (swapped when turned), so squarer screens (iPad: 506 at 1180×820, 545 at 1024×768) fill the screen and the extra height goes to the table; phones (≈ 390) and wide laptop windows (390; slim side bands) are unchanged. `s` (insets) is read before this in `st()`. Not turned on a sideways phone; turned −90° only when the screen is upright (W < H, any device), then fitted above the bottom inset (`H − s.b`) so it clears the home bar. Laptops: scaled up, centred.
- Flipped 2-player (Knucklebones, Othello; rules scoped `body.flip`): banner 64 (upside-down title) · game 603 · banner 64 · bar 36 · gap 30. Knucklebones: no "Pass & Play" label; empty difficulty row hidden in 2-player.
- Panels capped at 572 stage units on every screen (`.panel{max-height:572px}`); Remi's and Sudoku's Rules scroll (Sudoku's is 610; user, Nov 13: "let it scroll").
- Every game paints its background on `html` (body and #app transparent); the page behind the games uses the same background.
- Safe-area insets read from a hidden probe on the cover; games use `parent.__safe()`; `window.__SAFE` overrides for tests.
- Sideways phones (touch, short side < 600) stay upright: rotation is part of the stage transform. Exception: Remi Medias Landscape (above). Small Android tablets sideways with under 600 of height are treated the same (page shown turned; noted, left).
- Screens checked in pass 9 (scale 1.00 = iPhone 12 app): iPhone apps 0.96–1.10; iPhone 12 in Safari 0.83; iPhone SE in Safari / 320×568 about 0.70; Android 0.80–1.06; iPad upright 1.33–1.68; iPad sideways 0.90–1.26 using 30–35% of the screen; laptops 0.74 (1280×593) to 1.19 (1920×945), about 24% of the window. User: leave wide screens as they are, and no install hint on the cover.

## All games: shared rules
- Naming: the other side vs the CPU is "CPU" everywhere. British spelling. Levels "Easy / Normal / Hard" in every game (Remi said "Norm" until PR #71; its speed is "Slow / Normal / Fast").
- Settings order: the red button (Cancel game / New game / Reset) is the last row, then the notes. Message line under the play area in every game.
- Locked difficulty (Knucklebones, Othello): dimmed (`lk`, `aria-disabled`); a tap shows "Finish or cancel this game to change level." for 2.5 s (`flash()`). A difficulty picked before the first move isn't saved (user, Nov 13: leave).
- All confirmations "Tap again" (Cancel game, Reset, New game, Remi's Board, Water Sort's lower difficulty); the red Settings buttons use the core's `naArm` (3 s). Exit and Remi's landscape ✕ never ask.
- End light (PR #38): Sudoku's diagonal light (0.7 s, background only, 45 ms steps) in the winner's colour, yellow on a tie; plays once (not on reopening); off with reduced motion. Sudoku orange on solve; Knucklebones the winner's board (cyan you/P1, magenta CPU/P2); Othello the whole board; Water Sort cyan overlay across tubes (60 ms steps); Remi the score table in the closer's colour, match winner's at match end, yellow if nobody closed.
- Saved data is never trusted (PR #44, completed in PR #71): each game validates saves and starts fresh if damaged (Knucklebones grid/dice/turn; Othello board/undo incl. the undo `floor`; Water Sort 10 tubes × 4 layers, undo entries `{ts, moves}`; Sudoku `okGame`: level, 81 givens/values/notes/fix in range, a valid solution matching the givens, undo steps; Remi `okSave`: tile ids real, none twice, 4 players, number scores, whole round number, plain round results since those are written into the page). Records and levels are cleaned on load (`cleanRec` in Knucklebones/Othello, unknown difficulty → Normal; Water Sort `okN`: level 1–99,999; Sudoku `clean`; Remi `remi_rec`, `remi_set` only known values). Keep this when adding saved fields (`save_fuzz.py`).
- Saved records in Settings (muted colour): Knucklebones/Othello "Won vs CPU" per difficulty (`kb-rec`, `oth-rec` = [wins, losses, ties]); Sudoku solved per difficulty (`sdk-solved`); Water Sort solved + best level (`ws_solved`); Remi matches per CPU level (`remi_rec`). Games in progress resume (`kb-game`, `oth-game`, `ws_game`, `sdk-game`, `remi_game2`); header stats `kb-stats`, `oth-stats`.
- Sound and Scanlines (PR #71, user: "set scan and sound in any game and all five follow but reset every time the app opens"): kept on the cover (`naShared`, `naShare(k, v, from)`), each game's `naSet` applies them; never saved. A game that isn't on screen makes no sound (`naHid`), so CPU turns that finish after Exit are silent.
- Sound unlock (core, all five since PR #71; before only Knucklebones had the loop): a tap on the Sound switch sets `navigator.audioSession.type='playback'` (plays with the ringer off) and starts a silent looping WAV (older iPhones); a game that got Sound from another game unlocks at its first tap; the loop pauses when the cover takes over. Confirmed by the user on the iPhone (Nov 13).
- Touch (PR #71): `touch-action:manipulation`, no text selection, long-press menu or grey tap flash, in every game and on the cover (before only Water Sort and Remi). Pinch-zoom still works. Mouse users: buttons and cover cards brighten under the pointer (`filter:brightness`, only `(hover:hover) and (pointer:fine)`). Keyboard focus is still lost after each move (user: hover glow only). `touch-action:manipulation` also means quick repeated taps each fire a click (no double-tap zoom delay), which the secret Medias taps rely on.
- Anything that scrolls must also move with a mouse: hidden scrollbars leave a laptop user stuck (Remi, PR #72).
