# Neon Arcade – design notes

Details behind the project instructions: how things work now and why. One doc for everything: add new topics here, not in separate small docs. History is kept short (one line per change at the end); the long logs of the QA passes and the AI build are in git history (this file before the Nov 17 clean-up).

## Workflow
- Work and test locally; push only when the user says "deploy" (= push a branch, open the PR, **wait for the `checks` run on it to pass**, merge it; no review needed). `main` is the live site (GitHub Pages). GitHub deletes each branch on merge, so only `main` should exist.
- Automatic checks: `.github/workflows/checks.yml` runs on every pull request: `build_check`, `layout_compare origin/main`, `exit_check`, `core_check`, `resume_check`, `install_check` (about 5 min). Poll `gh api repos/Need4INK/neon_arcade_90s/commits/SHA/check-runs` until `checks` is `completed` / `success`. If a check fails, fix it first; don't merge around it.
- In Claude Code sessions `gh pr create` (GraphQL) is blocked: use the REST API (`gh api repos/Need4INK/neon_arcade_90s/pulls …`, then `-X PUT …/pulls/N/merge`, squash) as **two separate calls**. Pushing needs the repo added with push access. If the auto-mode check blocks a push, merge or a build from a fresh clone, it goes through once the user confirms in the chat. Branches can't be deleted through the connection. The Pages build status can't be read through the proxy.
- A deploy turn can be cut off (the cloud session restarts): on "deploy", first look at `git log`, `git ls-remote --heads origin` and the open pull requests; if the branch and PR already exist, compare them with the local work instead of pushing again.
- Commit before `git rebase` (a dirty tree stops the rebase, and a chained push then pushes an empty branch).
- After a deploy the user fully closes and reopens the home-screen app; Pages takes a minute or two.
- Layout ideas: try them on the screen test repo first (https://github.com/Need4INK/iPhone12_screen_test, live at https://need4ink.github.io/iPhone12_screen_test/; it can hold a copy of the next build as `arcade.html`; shares the arcade's Safari storage, accepted).
- Look choices: render the options on the real game (inject CSS, screenshot), on every colour involved; the user picks from labelled side-by-side composites (PIL, 2×2 or 3×2: now vs options). Generic mock-ups mislead. A quick inline SVG sketch is fine for placing elements.
- Design questions: when the user asks for options or an opinion, give a short numbered list with a recommendation; build only after they pick. Matters of taste "one at a time": one AskUserQuestion per item.
- These notes exist twice: in the claude.ai Project (`claude/design-notes.md`, the one Claude reads) and in the repo (`claude/`, together with `ai-blueprint.md`, `ai-tuning-prompt.md` and `project-instructions.md`), so they survive without a Claude subscription. Change both together: edit the repo copy, upload it to the Project with `project_write` + `local_path`, and ship the repo copy with the next deploy. If the user changes the Project instructions, refresh `claude/project-instructions.md` too. The repo copies are public on the live site (`/claude/…`); the user knows. The Remi rulebook PDF stays only in the Project.

## Testing
### Scale to the change
- Every change: rebuild, open the changed game at the iPhone 12 simulation and 320×568, no console errors; `layout_compare.py` (40 screens, expect 0 differences). GitHub repeats the quick checks on the PR.
- Core changes (`core.css`, `core.js`, `stage.js`): all five games; `core_check.py`; if the look must not change, `style_snapshot.py` before and after.
- Remi changes: also `remi_check.py`, both skins (Neon, Medias), and Medias Landscape (844×390 with `__SAFE={t:0,b:21,l:47,r:47}`, iPhone 12 upright = turned, iPad 1180×820 and 1024×768, 1280×800 / 1366×657, 320×568). Landscape: the round results fit the table without scrolling (`#table` scrollHeight ≤ clientHeight), on the iPhone above all, and 3 rows of formations show without scrolling (also with a hand over 18 tiles). Anything that scrolls: `mouse_scroll_check.py`. Saved-data changes: `resume_check.py`, `save_fuzz.py`. sw.js / manifest: `install_check.py`. Exit / history: `exit_check.py`.
- CPU changes: see CPU brain › Tests.
- Small behaviour-only changes: build_check, core_check, layout_compare, exit_check, resume_check, mouse_scroll_check, remi_check, plus a new check for the behaviour.
- Layout or template changes: full set incl. both flipped 2-player modes (Knucklebones, Othello), 844×390 sideways and 1280×800; `device_sweep.py` for the wider range.

### Simulating devices
- iPhone 12 app in headless Chrome: viewport 390×797, `screen` 390×844, `window.__SAFE` on the cover, inject `.bar{padding-bottom:34px}` into each game (harmless: the core's `main>.bar` rule outranks it). iPad: viewport = screen 1180×820 or 1024×768, `has_touch`, `__SAFE={t:24,b:20,l:0,r:0}`. Windows laptop windows: 1366×657, 1536×730, 1920×945, `__SAFE` all 0, no touch (the user plays Remi Medias on a Windows laptop with a mouse).
- Real-phone-only problems (clipping of fixed elements): show measurements on the phone and ask for a screenshot.
- Headless Chrome is not Safari: blend modes, overlays, SVG filters and SVG clip paths can look right here and wrong or blurry-when-zoomed on the iPhone/iPad. Prefer plain drawing and ask for a screenshot after deploying.
- The live site can't be fetched from the shell (proxy 403): use a local `http.server` (the service worker runs on localhost; add `Cache-Control: max-age=600` to mimic Pages).
- The packed page's CSP blocks `eval`: Playwright `wait_for_function` with a string fails; poll with `evaluate`.
- Installability: Chrome's `Page.getInstallabilityErrors` is only right in a persistent profile once the worker controls the page; test from a subfolder too (live site is under `/neon_arcade_90s/`).

### Reaching game state in tests
- Sudoku, Knucklebones, Othello use page globals; Water Sort keeps state in a closure (read `ws_game` from localStorage or use a never-shipped test copy). The core's `sndOn`, `AC`, `naKeep`, `panel`, `showPanel` are globals in every game frame. Bar buttons in every game: `bRules`, `bSet`; Exit is `#bar .mnu`.
- Remi: `window.__remi` (its own functions aren't reachable; hook state, e.g. `G.disc.splice` / `G.disc.push`, as `remi_check.py` does; `__remi.viewOf(p)` and `__remi.brain` are the CPU's view and decision functions; tile id = colour×13 + number − 1, +52 for the second set, jolys 104/105). For deeper checks, a never-shipped copy in /tmp with `ev:s=>eval(s)` added to `__remi` (rebuilt there, served with `start_server(port, root=…)`), e.g. round results at once: `__remi.ev("G.phase='play';endRound(1,G.pl[1].hand[0],'')")`. Formations without the test copy: set `__remi.G.melds=[{t:[ids],o:owner},…]`, push to `G.disc`, tap Sort (the `STRESS` snippets in `device_sweep.py` and `FULL` in `mouse_scroll_check.py` do this). In the draw phase a tap on a rack tile does nothing: tap Draw first. Measure Landscape at 844×390 (the turned version gives rotated rects). Doubles swap: set the deal through `__remi.G` (hands, `cur`, `starter`, `tn=0`, `phase='dbl'`), then `sel.add(id)` and `hSwap()`. Auto-play: per phase click Play / Draw; in `play` lay `__remi.openFor(hand)` / `findBest(hand,1,false)` melds via `sel` + `hLay()` (from `G.tn>=4`), then discard; speed via `__remi.spd=2`.
- Remi always opens in Neon: for Medias / Landscape click the title 5 times (`main>h1`, within 2 s) (with JS: `for(let i=0;i<5;i++)document.querySelector('main>h1').click()`), then Settings › Landscape view with JS (`document.getElementById('tgLay').click()`; the row is hidden in Neon, so use `evaluate`); `remi-rules-seen` skips the first Rules.
- Damaging a saved game: a game left open can save itself when the page closes (Sudoku on `pagehide`) and overwrite the damaged value. Remove the iframes first (`save_fuzz.py` does), or set the game's state to null.

### The checks in `tests/` (see `tests/README.md`)
- Run from the repo root after rebuilding; output to `tests/out/`. `harness.py`: server, phone sizes, iPhone 12 simulation; card ids `kb`, `oth`, `ws`, `sdk`, `rem`; helpers `open_page`, `open_game`, `game_frame`, `close_panel`, `to_cover`; `strict()` makes a printed False or console errors end with exit code 1.
- `build_check`, `layout_compare` (template positions vs any commit; banner and bar only), `core_check`, `mouse_scroll_check`, `style_snapshot` (`save NAME [folder] [sizes]`, `compare A B`; about 5 min a snapshot; two runs of one build compare equal, except laptop Remi Landscape's wide rack hover/scroll, a known flake), `device_sweep` (36 sizes, about 25 min), `resume_check`, `remi_check` (about 5 min, run it in the background), `remi_fair` (about 30 s), `install_check`, `icon_preview`, `colour_blind_check`, `a11y_check`, `save_fuzz` (about 8 min a game), `referee` (`kb N` needs the game count), `puzzle_check` (`sdk N` needs a count), `monkey` (one or two at a time), `exit_check`, `ai_tournament`, `ai_kit_check`, `adapt_check`. Reuse and extend them.
- `remi_check.py` rarely prints "VIOLATION opening: … 0 pts": its 20 ms poll can look after the table was cleared. Test race, re-runs clean.
- Two builds of the same sources give the same bytes; another fontTools version may pack the fonts differently, so `build_check` leaves the font data out.
- Long runs: start them as one background command (no `&` inside a foreground command: orphans fight over the ports) and stay in the turn polling; background work stops when the turn ends. Don't `git stash` while a test server serves the repo. The cloud session can restart mid-turn (background jobs gone, files kept): run long tournaments as a queue of pieces under 10 minutes that each write their result to a file and are skipped when done, and commit work in progress locally.

## How the pack works
- `index.html` is built by `games/build.py`: each game embedded as text in its own full-screen iframe (`srcdoc`), so games never clash and a game in progress survives switching. Build: `python3 games/build.py games/Knucklebones.html games/Othello.html games/Water_Sort.html games/Sudoku.html games/Remi.html index.html`
- Shared core, kept once in `games/` and put into each game by the build: `core.css` (first style in the head, so a game's own rules can differ: palette, page, the template in both forms, title, bar with Exit, Rules/Settings panel, rows, switches, action buttons, touch, hover, reduced motion); `stage.js` (runs before the page is drawn: scales/turns the block, sets `html.rot` / `r270` so scanlines follow a sideways picture, `--st`, `--sh`, `--stw`); `core.js` (right in front of the game's own script: `audio`/`tone`/`sfx`, sound unlock, `showPanel`, `setSw`, panel placing, outside tap / Escape, `naFirstRules`, Sound and Scanlines switches and their sharing, Exit, "Tap again" `naArm(button, fn)` / `naDisarm`, and the CPU brain kit). A game sets `naSfx` (its sound table) and `naSync` (refresh of its Settings rows); its file ends with a short "differs from the shared core" block. Knucklebones keeps its own `sfx(n, delay)`. Game files don't work opened on their own (accepted).
- The build drops whole-line `//` comments from `core.js` and each game's script (`no_comments`; a line inside a template string left open across lines, or after a line ending in a backslash, is kept). Page about 390 KB. Possible later: pack the core once on the cover and let games copy it, like the fonts (about −50 KB).
- The build also packs the fonts (see Fonts) and the QR, and wraps everything in the cover. The Exit button is in each game's markup (`<button class="mnu">`); the core closes any open panel (sends Escape), then calls `parent.kbShowCover()`.
- `kbShowCover()` shows the cover at once, then removes the game's history entry with one `history.back()` (an installed Windows Chrome app never fired `popstate`). Presses during the step back are ignored (`leaving`, 1.5 s); opening a game while a game entry is current replaces it. `showCover()` first tells the game on screen it is being left: `naPause()` (stops the silent sound loop) and `naLeave()` if the game has one (Remi: forget Medias).
- The URL never changes (no `#game`): bookmarks and the home-screen app always open on the cover. Page title "Neon Arcade"; `apple-mobile-web-app-title` sets the home-screen name.
- The cover page itself (in `build.py`) keeps its older layout with `html.stg … !important` rules on top, because it holds the iPhone frame handling.

## iPhone frames
- Each home-screen icon is its own app: frame (solid / see-through status bar) fixed when added; own saved data.
- iPhone 12 measured: `innerHeight` 797, `screen.height` 844, `100svh`/`100dvh` 797, standalone true. Solid icon: insets 0/34. See-through icon (the one the user keeps): insets 47/34, page starts behind the status bar but the fixed layer is cut at 797.
- Fix: the cover detects see-through (top inset > 0, portrait, `innerHeight < screen.height`, `innerHeight + top inset == screen.height`), adds `html.full` and `--fullh`; html/body are that tall with overflow hidden, cover and game iframes `position:absolute`; touchmove blocked. Once full, iOS may report `innerHeight` 844: both 797 (+inset) and 844 count as full (avoids flicker).
- Rotation: iOS updates insets late; the cover re-checks at 100/300/600/1000/1600 ms after rotating and on pageshow / foreground.
- Old solid icons keep a status-bar band; backgrounds fade from `#07030f` over the top 64px so there's no seam. Re-adding the icon gives the see-through frame.

## Three-area template (`core.css`)
- iPhone 12, top to bottom: safe top 47 · banner 64 · game area 667 · bar 36 (buttons flush with its bottom: padding 22px 0 0) · gap 30 = 844.
- The 390 × 797 block is scaled as one: `naCalc` (shared by the cover and `stage.js`) places a fixed stage below the top inset, k = min(width/390, (height − top inset)/797), centred; bottom inset ignored (the gap covers the home bar). No narrow-phone or short-screen variants: Settings buttons 64px everywhere.
- Game elements are centred by title `margin-bottom:auto` and bar `margin-top:auto`. Knucklebones: 8pt above/below the boards, boards grow (`flex-grow:8`). Remi: the game fills the game area 8pt clear of banner and bar (`#game` flex 1, `#table` flex 1 1 0 with `height:auto!important`, min 96; at the end of Remi's own CSS); the table takes the room left (about 360 tall on the iPhone 12), shrinks when the rack needs a third row, scrolls when melds overflow. Water Sort tubes max 64px wide.
- Landscape block (only Remi's Medias Landscape, `html.lnd`): `stage.js`'s `st()` (exposed as `window.naSt`, called by the game when the class changes) uses a block 750 wide (`NA_W`, width via `--stw`; = iPhone 12 landscape minus the 47 side insets, so k = 1 there). Height `NA_H = clamp(390, round(750 × ch / cw), 560)` (cw/ch available width/height, swapped when turned), so squarer screens (iPad: 506 at 1180×820, 545 at 1024×768) fill the screen and the extra height goes to the table; phones and wide laptop windows stay 390. Insets are read before this in `st()`. Not turned on a sideways phone; turned −90° only when the screen is upright (W < H), then fitted above the bottom inset. Laptops: scaled up, centred, slim side bands.
- Flipped 2-player (Knucklebones, Othello; rules scoped `body.flip`): banner 64 (upside-down title) · game 603 · banner 64 · bar 36 · gap 30. Knucklebones: no "Pass & Play" label; empty difficulty row hidden in 2-player.
- Panels capped at 572 stage units (`.panel{max-height:572px}`); Remi's and Sudoku's Rules scroll (user: "let it scroll").
- Every game paints its background on `html` (body and #app transparent); the page behind the games uses the same background.
- Safe-area insets read from a hidden probe on the cover; games use `parent.__safe()`; `window.__SAFE` overrides for tests.
- Sideways phones (touch, short side < 600) stay upright: rotation is part of the stage transform (exception: Remi Medias Landscape). Small Android tablets sideways with under 600 of height are treated the same (noted, left).
- Scales measured (1.00 = iPhone 12 app): iPhone apps 0.96–1.10; iPhone 12 in Safari 0.83; 320×568 about 0.70; Android 0.80–1.06; iPad upright 1.33–1.68; iPad sideways 0.90–1.26 using 30–35% of the screen; laptops 0.74–1.19, about 24% of the window. User: leave wide screens as they are; no install hint on the cover.

## All games: shared rules
- Naming: the other side vs the CPU is "CPU" everywhere. British spelling. Levels "Easy / Normal / Hard" in every game; Remi's speed "Slow / Normal / Fast".
- Settings order: the red button (Cancel game / New game / Reset) is the last row, then the notes. Message line under the play area in every game.
- Locked difficulty (Knucklebones, Othello): dimmed (`lk`, `aria-disabled`); a tap shows "Finish or cancel this game to change level." for 2.5 s (`flash()`). A difficulty picked before the first move isn't saved (user: leave).
- On/Off switches (`.tg[role="switch"]`, core.css) are sliders (user, from a mockup): pill, knob left and dim (`--line` border, `--mut` knob and word) when off, right and green with glow when on; the On/Off word sits beside the knob (`setSw` unchanged). Same 64px width, same height as the buttons. Medias (Remi.html): tan track `#c4a56a` with a dark-green knob when on, ivory knob on felt when off, 76px.
- Settings rows with 3+ choices are a level meter (user picked option C of three mock-ups: sliding pill, notched track, level meter): one pill track (`.seg.mtr`, 2px `--line` border, 2px padding, no gap), filled from the left up to the picked choice (`::before`, green at 22%, width = (i + 1) / n of the track), the picked choice a solid green pill, choices before it green, after it `--mut`. Same width and height as the old buttons. `naMtr()` in core.js sets `.mtr`, `--i`, `--n` on every `#pSet .seg` with 3+ buttons (a MutationObserver on `#pSet` keeps it current, so games need no code). Rows: Water Sort and Sudoku difficulty (Sudoku 4 choices, 62px each so label and meter share one line, user), Remi CPU level / speed / Target, and Knucklebones / Othello's on-screen difficulty (`#diff` marked `data-mtr`, also observed; buttons padding 6.5px so the row stays 30 tall; locked = dimmed `.lk`). Core rules are on `.mtr` (any container). Two-choice rows become meters only when marked `data-mtr`: Knucklebones Mode and Board, Othello Mode (user; Mode is 2 × 134 wide). Other two-choice rows stay separate pill buttons. Medias: tan pill, tan fill at 30%, ivory / muted words, pill shape kept (user). Water Sort's "Tap again" keeps its magenta pill (`.seg.mtr button.arm` padding 4.5px 2px so the row height holds).
- Every Settings button is pill-shaped (`border-radius:99px` on `.seg button, .tg`; Medias too; user).
- All confirmations "Tap again" (Cancel game, Reset, New game, Remi's Board, Water Sort's lower difficulty); the red Settings buttons use the core's `naArm` (3 s). Exit and Remi's landscape ✕ never ask.
- End light: Sudoku's diagonal light (0.7 s, background only, 45 ms steps) in the winner's colour, yellow on a tie; plays once (not on reopening); off with reduced motion. Sudoku orange on solve; Knucklebones the winner's board (cyan you/P1, magenta CPU/P2); Othello the whole board; Water Sort cyan overlay across tubes (60 ms steps); Remi the score table in the closer's colour, match winner's at match end, yellow if nobody closed.
- Saved data is never trusted: each game validates saves and starts fresh if damaged (Knucklebones grid/dice/turn; Othello board/undo incl. the undo `floor`; Water Sort 10 tubes × 4 layers, undo entries `{ts, moves}`; Sudoku `okGame`: level, 81 givens/values/notes/fix in range, a valid solution matching the givens, undo steps; Remi `okSave`: tile ids real, none twice, 4 players, number scores, whole round number, plain round results since those are written into the page, `own`, `mem` via `okMem`). Records and levels are cleaned on load (`cleanRec` in Knucklebones/Othello, unknown difficulty → Normal; Water Sort `okN`: level 1–99,999; Sudoku `clean`; Remi `remi_rec`, `remi_set` only known values); adjustments (`*-adapt`) count as 0 when damaged. Keep this when adding saved fields (`save_fuzz.py`).
- Saved records in Settings (muted colour): Knucklebones/Othello "Won vs CPU" per difficulty (`kb-rec`, `oth-rec` = [wins, losses, ties]); Sudoku solved per difficulty (`sdk-solved`); Water Sort solved + best level (`ws_solved`); Remi matches per CPU level (`remi_rec`). Games in progress resume (`kb-game`, `oth-game`, `ws_game`, `sdk-game`, `remi_game2`); header stats `kb-stats`, `oth-stats`.
- Sound and Scanlines (user: "set scan and sound in any game and all five follow but reset every time the app opens"): kept on the cover (`naShared`, `naShare(k, v, from)`), each game's `naSet` applies them; never saved. A game that isn't on screen makes no sound (`naHid`), so CPU turns that finish after Exit are silent.
- Sound unlock (core, all five): a tap on the Sound switch sets `navigator.audioSession.type='playback'` (plays with the ringer off) and starts a silent looping WAV (older iPhones); a game that got Sound from another game unlocks at its first tap; the loop pauses when the cover takes over.
- Touch: `touch-action:manipulation`, no text selection, long-press menu or grey tap flash, in every game and on the cover. Pinch-zoom still works. Quick repeated taps each fire a click (the secret Medias taps rely on it). Mouse users: buttons and cover cards brighten under the pointer (`filter:brightness`, only `(hover:hover) and (pointer:fine)`). Keyboard focus is still lost after each move (user: hover glow only).
- Anything that scrolls must also move with a mouse: hidden scrollbars leave a laptop user stuck.

## Accessibility
- Optional Accessibility switch in Settings of Water Sort, Remi, Sudoku (off by default; `ws_sym`, `sym` in `remi_set`, `sdk-sym`). Marks always in the page, shown by `body.sym`; code keeps `sym` / `.sy`.
- Water Sort shapes (`.sy.s0`–`.s8`): magenta circle, cyan square, yellow triangle up, orange diamond, green plus, purple triangle down, red X, white bar, blue two bars.
- Remi: mark bottom-left on every tile (red one bar, yellow two, blue three, white/joly none), clear of the atu-twin dot top-right; doubles bar sits above it while on (`bottom:7px`). Not in the Medias skin (switch hidden there).
- Sudoku: a bar under the numbers you entered (not given or hinted).
- Why: Water Sort unplayable red/green-blind; Remi blue vs white and Sudoku cyan vs white close for red-blind. Othello discs, Knucklebones x2/x3, Remi player colours fine or backed by another cue.
- Contrast: all active text passes. Tap targets: many under Apple's 44px (all above 24px at scale 1; about 20px on the smallest screens); left as is (user).

## Games
- Knucklebones: placed die = square face centred in its wide cell (`.cell.f .pips`, `min(100cqw,100cqh)`, x2 yellow / x3 orange). Die box hidden at game end. End message and Play again on one line (`.msg.end`: flex, text no wrap; user), except the flipped two-copy end. 2-player flipped end: two copies of the result + Play again side by side, left one upside down, short form "P1 wins 57–47!" (`.mid.two`, `#msg2`). Its second title is a `div.ttl2` (the others use `h1#t2`); the core styles both.
- Knucklebones turn hand-over: the placed die leaves the box at once (`hide`); the empty box keeps the mover's colour 0.2 s, then fades to the next player's (`show`, `paintDie()`, no grid rebuild so hit animations aren't cut); then the next die spins in (`.die.roll`, 0.3 s) and only then are columns tappable. 0.45 s per hand-over. Saves stay valid mid hand-over. Why: the old die lingered while the box changed colour, so it looked like the other player's.
- Othello: Undo vs CPU takes back your move and the reply; 2-player only until the other moves. Settings label "Allow undo". End messages end with a full stop; after reload "Your move". Difficulty row sits ~50px lower than Knucklebones' (accepted). Its Settings buttons are all double width. CPU: see CPU brain.
- Sudoku: generated on the phone (symmetric clue removal, unique solution), graded by technique: Easy ~38 naked singles, Normal ~30 hidden singles, Hard ~25 pointing/claiming/naked pairs, Master ~22 beyond. ## CPU brain
Goals, principles and acceptance targets: `claude/ai-blueprint.md`. Tuning from the user's play: `claude/ai-tuning-prompt.md`.

### Shared kit (end of `core.js`)
- `naRng(seed)` / `naR` (seeded random, never touches `Math.random`, so seeded tests keep their sequence), `naThink(fn,{min,max,ok})` (visible pause, cancelled when `ok()` turns false), `naSearch` + `naTick` (deeper each round, keep the deepest finished depth), `naWorker(work,helpers)` (blob: Worker, falls back to the main thread), `naChoose(moves,{temp,blind})` (the one mistake model; a move's `miss` makes it easier to overlook; no random moves), `naLevel` / `naKnobs(game,level)` (knobs per game and level), `naAdapt` / `naAdaptNote` (adjusting, below), `window.__ai` (seed, adapt, fast, main, pick, level, log, tm) for tests.
- Fair: CPUs decide from what a person at the table could see plus their own hand/die. Dice, deals and reshuffles stay `Math.random`; no level or adjustment touches them.
- Interruptible: `gid` / `token` checks; Exit, Cancel, New game stop a CPU turn at its next step, late answers are dropped.

### Othello (`othAI(d)` in `Othello.html`, runs in a Worker)
- Knobs `naLevel.oth`. Mailbox board (10×10) with make/unmake.
- **Easy** (`ev:'e'`, temp 3, blind .3): one move ahead; greedy for discs (light), mild square table, likes having moves, minds handing over a corner (`cg` 20). Blind spot = corners. Last 8 squares counted out exactly, still loosely.
- **Normal** (`ev:'h'`, depth 3, temp 2.5, blind .05): Hard's judgement, 3 moves ahead; a corner or a clearly best move (25+ ahead) is never overlooked.
- **Hard**: judgement by phase (mobility, frontier, corners, X/C next to an empty corner, stable edge discs, parity, late disc count); deeper each round, 120k nodes or 700 ms, whichever first; last 14 empties solved win/draw/loss (600k nodes); opening book of 41 + 38 lines found by this engine at depth 8 (script not kept; regenerate by searching each position, keeping the best moves for the book side and the top 3 within 8 points for the other).
- Pace (`pace()`): Easy 450–800 ms, Normal 550–900, Hard 650–1000; forced 280–450; book −150; close call +250, exact endgame +200; capped 1.5 s; search time counts.

### Knucklebones (`kbAI(d)` in `Knucklebones.html`, runs in a Worker)
- Knobs `naLevel.kb`.
- **Easy** (`ev:'e'`, temp 4, blind .4, kill .7, risk .1): one die at a time like a beginner: points now, a bit for knocking dice off, little worry about being hit back; blind spot = attacks.
- **Normal** (depth 2, temp 2, blind .05, obv 10): Hard's judgement, its die plus your reply.
- **Hard**: expectimax over dice, deeper each round (Star1 cut-offs, a position table), 3,000 nodes or 400 ms; judges a position as a chance to win (lead, exposure, tempo, placements left before a board fills: races to fill and plays the end out exactly).
- Pace: Easy 500–850 ms, Normal 600–950, Hard 650–1000; one open column 300–450; clear −150, close +250; cap 1.5 s.
- **The blueprint's 75% / 95% targets can't be met: the dice decide too much** (the strongest search tried beat Random only 84–86%). Realistic targets: Hard–Normal ≥ 57%, Normal–Easy ≥ 68%, Hard–Easy ≥ 75%; vs Random Easy ≥ 55%, Normal ≥ 75%, Hard ≥ 80%.

### Remi (`Remi.html`)
- **Fair by build.** Every CPU decision is `think(p, kind)` → `viewOf(p)` → a plain brain function (`rb…`, list `BRAIN`). The view holds only public things (discard row, table, joly-swap flags, each player's tile count / opened / board, pile size, turn numbers, the table's memory, match scores `sc`, target `lim`, round number `z`, speed `sp`, atu holder `atu`, points on the table `lp`) plus that CPU's own hand and its knobs. The brain never uses `G`; shared rule helpers take the table as a parameter (`trySwap(m,ids,S)`, `swapIdsFor(m,hand,S)`, `fitsTable(M,id,p)`). The game checks each answer against the rules before playing it (`layOk`, `doExtras`, take limits). Each decision gets its own seeded `naRng`. `__ai.pick({k,v,s},level)` answers a recorded view; `__ai.log` receives `[kind, seed, view, answer]`.
- **Table memory** `G.mem` (saved, `okMem`; reset each deal; restored by Undo): `h` = tiles seen going into a hand (taken from the row; the atu's twin), `no[p]` = the last 8 tiles player p discarded or passed on. Written for you and the CPUs alike (`takeRow`, `toDisc`, `notePass`, `noteAtu`).
- **Discards** (`rbKeep`, `rbRisk`, `rbDisc`): keep-value = pairs towards a run or set counted by the copies still out, + finished formations, + tiles that fit the table (incl. a joly's place in a run), − cost. Normal and Hard add the chance the next player can use the tile.
- **Taking** (`rbStart`, `rbEv`, `rbCan`): for each depth it may take at (up to `deep` back), the value of the turn vs drawing; `naChoose` picks (Easy overlooks takes, more the deeper). Looking further back is the biggest single lever.
- **Knobs** `naLevel.remi` (in `Remi.html`): Easy `deep 4, blind .25, pool 3, dtemp 6, span 4, slip .3, score .4`, no memory; Normal `deep 10, mem 1, safe 5, read .25, span 5, fade .06, fog .2, slip .1, shut 3, fish .3`; Hard `deep 20, mem 1, safe 5, read 1, look 4, guard .6, swap 1, span 12, fade .01, fog .03, slip .015, shut 3, fish .5, fin 1, cheap −2`, plus the imagining (below). Hard-only knobs are forced to 0 below Hard.
- **Personalities** `RSTY` (by seat; seat 0 has none; `knobsOf(p, lv)` = level knobs + style weights, `deep` multiplied; a style can hold its own values per level):
  - **Cautious** (CPU 1) `{draw:20, shy:4, solid:10, cheap:.2, wary:1, guard:.4, bd:1, look:2, normal:{draw:16}, hard:{solid:0, cheap:0, draw:10}}`: a take must beat drawing clearly, leftover tiles count against it; opens only with 55+ unless it's its 4th turn, someone is close or plays the board; throws costly tiles sooner; sees the end earlier; board game from 6 doubles.
  - **Bold** (CPU 2) `{deep:1.5, shy:-8, bd:-2, guard:-.6, safe:-5, easy:{deep:1.25}, normal:{deep:1.3}, hard:{look:-3.5}}`: looks further back, prefers the bigger take, opens and adds at once, board game from fewer doubles, no defence.
  - **Sly** (CPU 3) `{hold:1, fin:1, safe:3, shy:14, sand:1, fish:.3, easy:{shy:4, sand:0, fish:0}, hard:{shy:30, cheap:1}}`: once opened keeps formations in hand (`rbFree`) until it can go out or someone has 2 tiles; goes out with a 1 or joly (`rbFin`); minds the next player (you); small takes; opens small (`sand`).
- **Playing like a person** (each habit a knob, off at 0): imperfect memory (`span`, `fade`, `fog`; `rbH` gives each tile a fixed number per CPU and round, so what is forgotten stays forgotten, also after a reload); plausible misses (`slip`, scaled by how crowded the table is; `rbSees`: overlooks another player's formation for the whole turn; never its own, never with 4 or fewer tiles, never when working out whether it can go out); thinking time (`PW`, `rbW`: each choice says how hard it was; pause .45–1.5 of the speed step (Slow 1000 / Normal 600 / Fast 250 ms) × the style's tempo (Cautious +10%, Bold −12%) ± 15%; `cpuTurn` decides first, plays after the pause); reading the next player (`read`, `shut`); playing the score (`score`, `rbMood`: riskier behind, safer ahead, close fast near the target); fishing (`fish`, `rbWant`: throws, among tiles it would throw anyway, one next to a tile it hopes for); holding back (Sly).
- **Hard imagines hidden hands** (`rbWorld`, `rbTurn`, `rbQk`, `rbFitMap`, `rbVal`, `rbImg`): for the discard (up to 4 candidates) and take-or-draw (draw + up to 3 takes), it deals the unseen tiles at random many times (consistent with what was seen: no unlaid opening or formation in hands it would have laid), plays 10 turns of each by quick rules, values its points minus 0.3 × the others', and keeps its plain choice unless another is better by 2 standard errors and 1 point. 160 tables at Slow, 96 Normal, 40 Fast. Runs in a Worker built from `BRAIN` (`thinkW`, `brainW`), inside the move's pause (time taken off the pause; no answer within 1.5 steps = plain choice). Also: opens at once, holds costly tiles (`cheap −2`), goes out on a 1 or joly when it can, board game by expected points (`rbBoard`, `bev` 100, a style's `bd` moves it 40 a step: in practice 6 doubles, Bold 5 in its first turn), the atu's 50 count in the score play.

### Adjusting to the player
- After a whole game against the CPU, never during one, never at Hard, never in 2-player: Knucklebones and Othello note won +1 / lost −1 / tie 0; Remi notes your **place** when a match ends (1st +1, 2nd +1/3, 3rd −1/3, 4th −1). Saved as `kb-adapt`, `oth-adapt`, `remi-adapt` `{easy, normal}` in −1..1, each game moves it 20% towards the result (about the last 5). No UI; records unchanged.
- `naLevel[game].span[level]` = how far towards the next level at the sharpest (default Easy 90%, Normal a third; Remi Easy 50%); `naLevel[game].soft[level]` = the gentlest values (Knucklebones Easy `{temp 5.5, kill .5, risk 0}`; Remi Easy `{deep 2, blind .35, slip .4, span 3, dtemp 8, pool 4}`, Normal `{deep 8, span 4.5, fade .09, slip .13, blind .08, read .15}`); without `soft`, gentler mirrors sharper. Levels never overlap, also at the ends of the range.

### Tuning lessons and open points
- Remi: nearly every legal take is already taken (a take needs a new formation at once), so "wanting takes more" changes nothing; a margin on drawing (`draw`) is the cheap way to take rarely, counting leftover tiles (`shy`) keeps the hand small (and a small hand closes more). Looking less far back is expensive. Waiting with the opening costs 4–12 points. Going out on a 1 or joly is worth about +9 a round at Normal / Hard. Holding back costs nothing only if Sly lets go in time.
- Candidates for future tuning (each moves every level and style at once): the cost of a tile in hand (`v/12` in `rbKeep`; weighting it less scored more), the imagining's untuned numbers (`riv` .3, `sure` 2, `imk` 4, `imw` 3, `left` .6, `age` 0), a thrown tile that fits the table in the turn a CPU opens.
- A player who plays like the plain level wins about 20–22% of Remi matches at the CPUs' table (25% would be even). Remi CPUs read only the next player, so what you take and pass on is read by CPU 3 (Sly). Fishing can only be judged by a person. Without a Worker the imagining holds the screen up to ~350 ms at Slow (every target phone has Workers). The AI added about 49 KB, over the blueprint's 40.

## Fonts
- `games/fonts/`: PressStart2P and VT323 (OFL, licence texts included). `build.py` subsets them (fontTools; if it's missing, the whole font is packed), stores them as base64 in `<style id="nafonts">` on the cover, and puts a small script into each game that copies that style. Nothing is loaded from outside. Remi's Medias skin uses system fonts (Georgia, Arial Rounded MT Bold; Android falls back to its own serif/sans).

## Offline and install
- `sw.js` (CACHE `neon-arcade-v3`; next `neon-arcade-v4`): network-first with `cache:'no-cache'` (quick 304); after 3 s (`SLOW_MS`) shows the saved copy and saves the server's answer for next time; first visit waits. Copies keyed without `?query`; offline fallback: same address, saved start page, any page. Saves the start page on install and when the page asks; deletes old caches on activate; ignores anything not from the site.
- Bump CACHE only when sw.js changes (game, manifest and icon changes don't need it).
- `manifest.json`: "Neon Arcade", `start_url`/`scope` `"./"`, standalone, portrait, `#07030f`, icons `icon-192.png` + `icon.png` (any) and `icon-maskable.png`. No `id` (would resolve to `/`; without it the app ID is `/neon_arcade_90s/`). Portrait lock: the installed Android app doesn't rotate, so Remi Landscape shows turned there (iPhone ignores it).
- Installs as a Chrome app on Android and Windows.

## Security
- Static site; records only in each device's localStorage. Main risk: someone taking over the GitHub account (keep two-factor on; merge only the user's/Claude's PRs).
- No outside loads except the site's own og/share links; no forms, eval, fetch, XHR, WebSocket, beacons; `innerHTML` only gets the games' own strings and checked saved numbers.
- CSP meta in the cover (build.py, after `<meta charset>`; srcdoc frames inherit): `default-src 'self'; script-src 'self' 'unsafe-inline' blob:; worker-src 'self' blob:; child-src 'self' blob:; style-src 'self' 'unsafe-inline'; font-src 'self' data:; img-src 'self' data: blob:; media-src 'self' data: blob:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'none'`. `blob:` for the Workers, `data:` fonts, the Medias numbers and the silent WAV. Anything from outside gets blocked silently: pack it in instead.
- The GitHub workflow has `contents: read` only and installs Playwright and fontTools on the runner for the tests; nothing of that ships.

## Known limitations (accepted)
- Fixed-size games (Othello, Sudoku, Water Sort) sit centred with more space than Knucklebones and Remi.
- Remi's and Sudoku's Rules panels scroll.
- Many tap targets under 44px.
- Wide screens (laptops, sideways iPads) show the neon games and the cover as a centred column; only Remi's Medias Landscape fills them.
- Saves don't move between installs or devices (would need a server); a manual "Transfer saves" was offered and declined for now.
- Secret Medias is undiscoverable by design.
- Knucklebones' CPU levels are closer than the blueprint's targets (dice).
